把这个博客免费部署到 GitHub Pages

2025 年 12 月 30 日 ·约 6 分钟 ·你的名字

这个站点是纯静态的：没有构建、没有后端、没有数据库。 所以它天然适合托管在 GitHub Pages 上——免费、自带 HTTPS、推送即上线。 整个过程大约二十分钟。

一、准备：把文件放进仓库

站点根目录里需要有 index.html，其余文件按现有结构保持相对路径：

text 
blog/
├── index.html
├── archive.html
├── about.html
├── posts/
│   └── *.html
└── assets/
    ├── style.css
    ├── posts.js
    ├── site-config.js
    └── site.js

关键点：所有引用都用相对路径（assets/style.css、 ../index.html），不要写以 / 开头的绝对路径。 这样无论部署在 用户名.github.io 还是子路径 用户名.github.io/仓库名/ 下都能正常打开。

二、创建仓库并推送

bash 
cd blog
git init
git add .
git commit -m "init: 个人博客第一版"
git branch -M main
git remote add origin https://github.com/<你的用户名>/blog.git
git push -u origin main

三、开启 Pages（最简单的方式）

  1. 进入仓库的 Settings → Pages。
  2. Source 选择 Deploy from a branch。
  3. 分支选 main，目录选 / (root)，保存。
  4. 等一两分钟，访问 https://<你的用户名>.github.io/<仓库名>/。

如果域名打开是 404，先去 Actions 标签页看有没有失败的部署任务， 90% 的问题都在那里有明确的报错。

四、进阶：用 Actions 自动部署

分支方式已经够用，但如果你以后想加构建步骤（比如把 Markdown 编译成 HTML）， 用工作流会更有余地。在仓库里新建：

yaml 
# .github/workflows/pages.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .
      - id: deployment
        uses: actions/deploy-pages@v4

然后回到 Settings → Pages，把 Source 改成 GitHub Actions。之后每次 git push 都会自动发布。

五、自定义域名（可选）

  1. 在仓库根目录添加文件 CNAME，内容只有一行：blog.example.com。
  2. 在域名服务商处添加一条 CNAME 记录，指向 <用户名>.github.io。
  3. 回到 Pages 设置里勾选 Enforce HTTPS，证书会自动签发。
⚠️

域名解析生效可能需要几十分钟。这段时间里不要反复改配置—— 我当初就是因为等不及，来回切换导致证书签发了两次，最后白等一小时。

六、几个经验

  • 加一个 .nojekyll 空文件：避免 GitHub 用 Jekyll 处理你的文件， 导致下划线开头的目录被忽略。
  • 本地先预览一遍：直接双击 index.html 就能看， 不用装任何服务器。
  • 写文章只改一处：新增文章时在 assets/posts.js 加一条记录， 首页、归档、上下篇导航会自动更新。
  • 别用绝对路径：这是静态站点部署最常见的翻车点，样式丢失基本都是它。

小结

静态博客最大的好处是没有需要维护的东西：没有服务器要续费， 没有依赖会过期，十年后打开这几个 HTML 文件，它们依然能正常显示。 对一份希望长期写下去的笔记来说，这是很重要的性质。
