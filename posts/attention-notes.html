从零读懂自注意力：一份手写推导笔记

2026 年 3 月 18 日 ·约 12 分钟 ·你的名字

第一次看到 Attention(Q, K, V) = softmax(QKᵀ / √d_k) V 时，我的反应是： 这五个符号我每个都认识，连起来却完全不知道在干什么。后来我逼着自己把每个矩阵的形状、 每一行元素的含义都写出来，才意识到它其实是一件非常朴素的事情—— 用相似度做加权平均。

这篇笔记按我当时的理解顺序排列：先讲直觉，再讲符号，最后才落到代码和复杂度。

一、先忘掉公式：注意力就是加权平均

假设你有一句话，每个词已经变成了一个向量。现在你要重新表示第 i 个词，办法是：

  1. 让第 i 个词去「问」句子里所有词：你和我有多相关？
  2. 把相关程度归一化成一组权重，加起来等于 1。
  3. 用这组权重，把所有词的信息加权求和，得到新的第 i 个词。

就这三步。整篇论文要解决的，只是「怎么问」「怎么算相关」以及「怎么让它训得动」。

二、Q、K、V 分别是干什么的

把上面三步翻译成矩阵语言：

  • Q（Query，查询）：我要找什么。形状 [n, d_k]。
  • K（Key，键）：我身上有什么标签可供匹配。形状 [n, d_k]。
  • V（Value，值）：如果被选中，我实际贡献什么内容。形状 [n, d_v]。

它们都不是凭空来的，而是同一个输入 X（形状 [n, d_model]） 乘上三个可学习的权重矩阵得到的：

text 
Q = X @ W_Q      # [n, d_model] @ [d_model, d_k] -> [n, d_k]
K = X @ W_K
V = X @ W_V

QKᵀ 得到的是 [n, n] 的分数矩阵：第 i 行第 j 列， 就是「第 i 个词对第 j 个词的关注分数」。这就是 自注意力的「自」： Q、K、V 全部来自同一个序列。

三、为什么一定要除以 √d_k

这是最容易被当成「玄学调参」的一步，其实理由很干脆。

假设 q 和 k 的每个分量都是均值为 0、方差为 1 的独立随机变量， 那么点积 q · k 是 d_k 个独立项之和，它的方差就是 d_k。 维度越大，点积的绝对值就越容易飙到很大。

softmax 对大输入非常敏感：输入分布一旦被拉宽，输出就趋近于 one-hot， 梯度也随之趋近于 0——模型不是学错了，而是学不动了。 除以 √d_k 正好把方差拉回 1，让 softmax 工作在梯度健康的区间。

💡

记忆方式：除以 √d_k 不是为了归一化数值，而是为了归一化方差。 如果你哪天改了注意力打分的定义（比如加了相对位置偏置），就要重新想想这个缩放还有没有意义。

四、多头注意力不是噱头

单个注意力头只能给出一张「关注图」。但语言里的关系是多样的： 有的头在跟踪主谓一致，有的头在处理指代，有的头只盯着前一个词。 让一个头同时干这些事，它会选择妥协。

多头的做法是把 d_model 切成 h 份，每份独立做一次注意力， 最后拼接再投影：

text 
d_model = 512, h = 8  ->  每个头 d_k = d_v = 64
计算量几乎不变，但模型获得了 h 个不同的「观察视角」

注意总计算量：单头用 512 维做一次，和 8 个头各用 64 维做一次，代价接近。 所以多头是用同样的预算换来了表达多样性，这是它值得存在的理由。

五、一个能跑通的最小实现

下面这段代码去掉了所有工程包装，只保留数学本身，建议逐行对照上面的公式读：

python 
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class SelfAttention(nn.Module):
    def __init__(self, d_model: int, n_heads: int):
        super().__init__()
        assert d_model % n_heads == 0, "d_model 必须能被 n_heads 整除"
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads
        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.out = nn.Linear(d_model, d_model)

    def forward(self, x, mask=None):
        # x: [batch, seq_len, d_model]
        b, n, _ = x.shape
        # 1. 线性投影后拆成多头: [b, n, h, d_k] -> [b, h, n, d_k]
        q = self.w_q(x).view(b, n, self.n_heads, self.d_k).transpose(1, 2)
        k = self.w_k(x).view(b, n, self.n_heads, self.d_k).transpose(1, 2)
        v = self.w_v(x).view(b, n, self.n_heads, self.d_k).transpose(1, 2)

        # 2. 缩放点积打分: [b, h, n, n]
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float("-inf"))

        # 3. 归一化 + 加权求和
        attn = F.softmax(scores, dim=-1)
        ctx = attn @ v                          # [b, h, n, d_k]

        # 4. 拼回 [b, n, d_model]
        ctx = ctx.transpose(1, 2).contiguous().view(b, n, self.d_model)
        return self.out(ctx), attn


if __name__ == "__main__":
    torch.manual_seed(0)
    layer = SelfAttention(d_model=64, n_heads=4)
    x = torch.randn(2, 10, 64)                  # 2 条样本，长度 10
    y, a = layer(x)
    print("输出:", tuple(y.shape))              # (2, 10, 64)
    print("注意力权重行和:", a.sum(-1)[0, 0])   # 应当全是 1.0

最后一个 print 是我的自检习惯：softmax 的输出每行必须和为 1。 如果这里不是 1，八成是维度对错了，而这类错误往往会在训练几百步之后才以奇怪的方式暴露出来。

六、复杂度，以及两个我曾经搞错的地方

自注意力的时间和空间复杂度都是 O(n² · d)，n² 来自那张 [n, n] 的分数矩阵。这是长序列难做的根源，也是后来各种稀疏／线性注意力工作的出发点。

说法实际情况
「注意力权重就是模型的可解释性」 权重只说明信息流动的一个侧面，不能直接当作因果解释
「多头就是并行加速」 并行的确是工程收益，但它的设计动机是表达多样性
「除法是为了防止数值溢出」 溢出只是表象，根因是方差随维度增长导致梯度消失

小结

  • 注意力 = 用相似度做加权平均，Q/K/V 是三种角色而非三种数据。
  • 1/√d_k 的作用是稳住方差与梯度。
  • 多头用同样的预算换取多个观察视角。
  • 复杂度瓶颈在 n² 的分数矩阵。

下一篇我打算把位置编码也按这个方式推一遍，尤其是「为什么正弦函数能表达相对位置」这一步—— 我至今只在直觉层面接受它，还没真正算清楚。
